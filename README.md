# マリオテニス 対戦ナビ

大会中の対戦手順を補助するWebアプリ。`index.html` 1枚だけで動きます。
コート画像はファイル内にdata URIで埋め込み済みなので、追加のファイルは不要です。

## GitHub Pages への置き方

1. リポジトリを作る（例：`mt-navi`）
2. `index.html` をリポジトリの**ルート**に置いてコミット・プッシュ
3. リポジトリの **Settings → Pages** を開く
4. **Source** を `Deploy from a branch`、**Branch** を `main` / `/ (root)` にして Save
5. 1〜2分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

コマンドで作る場合:

```bash
git init
git add index.html
git commit -m "対戦ナビ"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

プライベートリポジトリだとGitHub Pagesは無料プランでは使えません。パブリックにしてください。

## スマホでの使い方

公開URLをスマホのブラウザで開き、ホーム画面に追加するとアプリのように全画面で使えます。
進行状況は端末内（localStorage）に保存されるので、途中でブラウザを閉じても続きから再開できます。

## 中身をあとから直す場所

`index.html` の `<script>` の先頭にまとまっています。

| 変えたいもの | 直す場所 |
|---|---|
| コートの名前・色 | `COURTS`（BAN単位の7枠） |
| コート決定で選ぶコート | `PICK_COURTS`（アカデミー／スタジアムに分割した10コート） |
| コート画像 | `FRAME_IMG`（BAN用・枠まるごと）／ `PICK_IMG`（決定用・上下に分割） |
| ルームIDの桁数 | `ROOM_ID_LEN`（現在 6） |
| ラケットの選択順 | `RACKET_STEPS`（現在 1P 1本 → 2P 2本 → 1P 1本） |
| コートBAN・決定の順番 | `courtSteps(i)`（i は 0=1戦目, 1=2戦目, 2=3戦目） |
| キャラクターピックの順番 | `charSteps(i)` |
| 対応ルール | `RULES` |

画像を差し替えるときは、`FRAME_IMG` / `PICK_IMG` の値を画像URL（`"courts/hard.jpg"` のような相対パスでも可）に書き換えてください。相対パスにする場合は、その画像ファイルも同じリポジトリに置きます。

保存データの形式を変えたときは `KEY`（現在 `"mt-navi-v5"`）の数字を上げると、古い保存データを読まずに済みます。

## 実装している大会ルール

- **コートBAN**：7枠単位。クレイ／ハード／グラスの枠はアカデミーとスタジアムをまとめてBAN
- **コート決定**：10コート単位。アカデミーとスタジアムを分けて選択
- **1戦目**：1P 1BAN → 2P 2BAN → 1P 決定
- **2戦目**：1P（前戦の勝者）2BAN → 2P 決定
- **3戦目**：1P（2戦目の勝者）2BAN ＋ 1戦目のコート枠を任意で3つ目に追加BAN → 2P 決定
- **1P/2P**：最初に1回だけ選択。2戦目以降は勝敗から自動判定（勝者が1P）
- **3戦目の実施条件**：2戦目終了時点で1勝1敗のときのみ
- **キャラクター／ラケット**：順番の案内表示のみ。記録欄は任意の自由入力
